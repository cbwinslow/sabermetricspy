# ADR-0059: Outside Tie-Outs Come From Recorded baseballr Runs

Status: Accepted

## Context
CLAUDE.md rule 7 requires an outside reference value for every shipped metric. An earlier draft fixture labelled "baseballr" held hand-typed numbers (one line did not add up) and a copy of our own RE24 table, so it proved nothing.

## Decision
`tools/baseballr_golden.R` runs baseballr (2.0.0, R 4.6.1) and writes `tests/golden/baseballr/baseballr_tieout.json` with the package version, calls and run date. `tests/test_golden_baseballr.py` compares only to that file: bundled seasonal constants against `fg_guts()` for every bundled season (1990-2025), `Metric.WOBA` against `woba_plus()` and `Metric.FIP` against `fip_plus()` on 8 lines each, within baseballr's own rounding (3 and 2 decimals). Inputs are chosen counting lines, not real players; the outputs are baseballr's.

One difference is recorded, not hidden: `fip_plus()` names its walk column `uBB` and so omits intentional walks if you pass it unintentional walks, while FanGraphs FIP counts them (tests/golden/pitching.yaml). The fixture passes total walks to `fip_plus()` so the same quantity is compared.

Not tied out: baseballr's RE24 table is an empirical 2026 matrix that cannot be rebuilt without its play-by-play, and `run_expectancy_code()` needs Statcast-shaped play data; neither is claimed as checked.

## Alternatives
- Call R from the test suite, not chosen now because CI would then need R and network; revisit if the fixture is regenerated often.
- Typed values from FanGraphs pages only, not chosen now because baseballr gives a second, scriptable source; revisit if baseballr changes its formulas.
- Tie RE24 to baseballr's matrix, not chosen now because the table is season-specific and unreproducible here; revisit when a play-by-play file with a published matrix is available.

## Consequences
The fixture is regenerated by one command and any drift shows as a test failure.
