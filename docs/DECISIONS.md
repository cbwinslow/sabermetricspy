# Architecture Decision Records (ADR Index)

This document records the foundational architectural decisions for `sabermetricspy`. New architectural changes require adding a new ADR entry here and following the OpenSpec change workflow (`openspec/`).

---

| ADR | Title | Status | Decision & Rationale |
| :-- | :--- | :--- | :--- |
| **ADR-0001** | **Spec-Driven & Test-Driven Workflow (OpenSpec + Pytest/Hypothesis)** | Accepted | All features follow OpenSpec (`openspec/`) proposals, specs, designs, and tasks paired with TDD (unit tests, `hypothesis` property-based identity tests, and golden cross-checks against FanGraphs, Baseball-Reference, Retrosheet, and `baseballr`). |
| **ADR-0002** | **Package Name `sabermetricspy` & Apache-2.0 License** | Accepted | Uses the standard SABR spelling (`sabermetricspy`) and `Apache-2.0` license for wide adoption, patent protection, and commercial compatibility. |
| **ADR-0003** | **Pure Calculation Core (No Network or Scraper I/O)** | Accepted | The core engine operates strictly on in-memory or lazy dataframe/arrow objects. Data acquisition lives in `retrosheetpy`, `chadwickpy`, `pybaseball`, or `dlt`/DuckDB pipelines. |
| **ADR-0004** | **Narwhals + PyArrow for DataFrame Interoperability** | Accepted | Formulas are authored once using `narwhals` expressions, giving native zero-overhead execution on Polars (`DataFrame`/`LazyFrame`), DuckDB (`DuckDBPyRelation`), PyArrow (`Table`), and pandas (`DataFrame`). |
| **ADR-0005** | **3-Tier Naming Convention** | Accepted | Tier 1 (`StrEnum` members) uses `UPPER_SNAKE_CASE` baseball acronyms (`Metric.WRC_PLUS`, `Stat.HR`); Tier 2 (canonical columns/functions) uses `lower_snake_case` (`"wrc_plus"`, `"hr"`); Tier 3 (`MetricSpec.display_name`) uses authentic baseball typography (`"wRC+"`, `"HR"`). See `docs/NAMING_CONVENTIONS.md`. |
| **ADR-0006** | **Two-Stage Additive Calculation & Ratio Rule** | Accepted | Stage 1 classifies play/pitch events into additive counts; Stage 2 sums counts across any grouping or rolling window before evaluating ratios. Ratios are never averaged. |
| **ADR-0007** | **Innings Stored as Integer Outs (`outs`)** | Accepted | Traditional baseball notation (`"6.2"` = $6\frac{2}{3}$ IP) is base-3 fractional notation and causes arithmetic bugs if treated as a float. All internal formulas use integer `outs` (`1 IP = 3 outs`), converting `"6.2"` only at I/O edges. |
| **ADR-0008** | **Strict Null & Zero-Denominator Policy** | Accepted | Missing count columns coerce to `0` only at ingestion presets; missing physical measurements (`launch_speed`) stay `null`; any division by zero evaluates to `null`/`NaN` (never `inf` or exception). |
| **ADR-0009** | **Decimal Rate Scale (`0.0` to `1.0`) Internally** | Accepted | Rate and percentage metrics (`AVG`, `OBP`, `BB_PCT`, `K_PCT`, `CSW_PCT`) are computed on a `0.0–1.0` scale internally so downstream equations (`K% - BB%`, `SIERA`, `wOBA`) never suffer from `* 100` scaling errors. |
| **ADR-0010** | **Automatic Metric Dependency Graph (DAG)** | Accepted | Metrics declare dependent metrics in `MetricSpec.requires` (e.g., `OPS` requires `OBP` and `SLG`; `WRC_PLUS` requires `WRAA` -> `WOBA`). The engine resolves topological order and computes each intermediate metric once. |
| **ADR-0011** | **Metric Suites (`MetricSuite`) & `calculate_available()`** | Accepted | Users can request individual metrics, curated suites (`MetricSuite.TRADITIONAL_BATTING`, `MetricSuite.DEFENSE_INDEPENDENT_PITCHING`, etc.), or `calculate_available(df)` to compute all metrics supported by `df`'s columns. |
| **ADR-0012** | **Code vs. Bundled YAML Separation** | Accepted | Core metric expressions and closed vocabularies (`StrEnum`) live in typed Python; seasonal constants (`woba_fangraphs.yaml`, `fip_constants.yaml`), source presets (`retrosheetpy.yaml`, `statcast.yaml`), and custom user formulas live in bundled YAML files loaded via `importlib.resources` and validated by Pydantic. |
| **ADR-0013** | **Immutable `CalculationResult` Return Type** | Accepted | `calculate()` always returns a frozen `CalculationResult` holding `.df` (in the caller's native dataframe type), `.specs`, `.context`, and `.summary()`, ensuring strict return typing and full provenance. |
| **ADR-0014** | **Scikit-Learn Estimator API + Statsmodels-Style Frozen Results** | Accepted | Fitted models (`RunExpectancyMatrix`, `LinearWeightsEstimator`, `MarcelProjector`, `Log5Model`, `MarkovChainModel`, `MonteCarloSimulator`) implement `.fit()`, `.transform()`, `.predict()` and expose a frozen `.results` object with standard errors, intervals, and diagnostics. |
| **ADR-0015** | **First-Class `retrosheetpy` & `statcast` Presets** | Accepted | Built-in presets map `retrosheetpy` (`events` 164-col cwevent schema and `gamelogs` 161-col schema) and Baseball Savant `statcast` pitch/batted-ball schemas directly into canonical `sabermetricspy` count and state columns. |
| **ADR-0016** | **Core Scientific Dependencies vs. Optional Extras** | Accepted | Pre-compiled scientific wheels (`narwhals`, `pydantic`, `numpy`, `scipy`, `scikit-learn`, `statsmodels`, `pyyaml`, `pyarrow`, `polars`, `pandas`, `duckdb`) are included in standard installs; C-compiler-heavy MCMC (`pymc`) is reserved as an optional `[bayesian]` extra. |
| **ADR-0017** | **Strict Tooling Gate (`uv`, `hatchling`, `ruff`, `pyright --strict`, `pytest`, `hypothesis`)** | Accepted | Every change must pass `ruff check`, `ruff format --check`, `pyright` in strict mode, and `pytest` (including `hypothesis` property tests and golden cross-checks). |
| **ADR-0018** | **Plugin Extensibility via Entry Points & `@register_metric`** | Accepted | Third-party packages can register custom metrics, models, and league constants via `@register_metric` or Python entry points (`sabermetricspy.plugins`). |
| **ADR-0019** | **100% Declarative YAML SourceTranslator & Nomenclature Registry** | Accepted | All column alias mappings and event-to-count translations are stored in declarative YAML files (`data/presets/aliases.yaml` and `data/presets/sources.yaml`) and executed by `SourceTranslator`. Users can add new providers or custom nomenclatures purely via YAML or `register_source_yaml()` without modifying core Python code. |
| **ADR-0020** | **288-State Count Expectancy (`RE288`), Win Probability (`WPA` & `LI`), and End-to-End Demo Suite** | Accepted | `CountExpectancyMatrix` (`RE288`) models all 288 `(outs, base_state, balls, strikes)` states for pitch run value and count leverage; `WinProbabilityModel` computes game-state win expectancy, `WPA`, Leverage Index (`LI`), and context-neutral wins (`WPA/LI`); runnable `examples/` scripts and an exhaustive test audit verify 100% of registered metrics, suites, and estimators. |
| **ADR-0021** | **Hybrid Speed Telemetry (`ExecutionProfile` + `sb.benchmark`) & `pytest-benchmark`** | Accepted | Every `CalculationResult` attaches a frozen `ExecutionProfile` (`.profile`) measuring nanosecond-precision stage timings (`translation_ms`, `normalization_ms`, `aggregation_ms`, `dag_eval_ms`, `total_ms`, `rows_per_sec`) via `time.perf_counter_ns()`. `sb.benchmark()` compares throughput across Polars, DuckDB, PyArrow, and pandas, while `pytest-benchmark` provides CI regression testing in `dev` dependencies. |
| **ADR-0022** | **Additive Rolling-Window Engine (`calculate_rolling`)** | Accepted | Rolling $N$-game or $N$-appearance metrics (`calculate_rolling`) sort by `(by, order_by)` and compute rolling window sums over all additive count columns (`rolling_sum`) before evaluating rate/ratio expressions—never averaging ratios. |
| **ADR-0023** | **Pitch-Tracking Physics (`VAA`, `IVB`, `HB`) & Statcast Expected Metrics (`xBA`, `xSLG`, `xwOBA`)** | Accepted | `SourceTranslator` converts Statcast 9-parameter kinematics (`vy0`, `vz0`, `ay`, `az`, `pfx_x`, `pfx_z`, `release_speed`, `release_spin_rate`, `release_extension`) and expected probabilities into additive sum/count columns evaluated by `MetricSuite.PITCH_PHYSICS` and `MetricSuite.STATCAST_EXPECTED`. |
| **ADR-0024** | **Command-Line Interface (`sabermetrics` CLI)** | Accepted | Exposes a `sabermetrics` CLI entrypoint supporting `list`, `info`, `suites`, and `benchmark` subcommands for terminal inspection and live benchmarking. |
| **ADR-0025** | **Decorator-Based Telemetry (`@profiled`) & Benchmark Registry (`@register_benchmark`)** | Accepted | `@profiled` wraps core functions, estimator methods, and user functions to automatically record `SpanRecord` timings, row counts, and backends into `sb.telemetry` (`PerformanceTracker`). `@register_benchmark` registers subsystem and custom workloads for execution via `sb.run_registered_benchmarks()` or `sabermetrics benchmark --registered`. |
| **ADR-0026** | **105+ Metric Registry & Open Modeled Estimators (`Stuff+`, `xwOBA`, `Framing`, `OAA`, `EmpiricalBayesShrinker`)** | Accepted | Expands the registry to 105 canonical metrics (`GPA`, `TA`, `RC27`, `QERA`, `DIPS_BOP_PCT`, `XERA`, `BAUER_UNITS`, `HAA`, `PUTAWAY_PCT`, `WGDP`, `BSR`, `PLI`, `WPA_LI`, `CLUTCH`, `REW`, etc.) and adds `EmpiricalBayesShrinker`, `ExpectedOutcomeModel`, `PitchQualityModel` (`Stuff+`/`Location+`/`Pitching+`), `CatcherFramingModel`, `OutsAboveAverageModel`, and `WARFramework.calculate_position_player_df()`, all decorated with `@profiled` and exposing frozen `.results`. |
| **ADR-0027** | **Published-Method Conformance, Sourced Constants, and Reference Status** | Accepted | Bundled constants are sourced FanGraphs Guts!/league-total snapshots (1990-2025) with optional, never-invented league values; FIP/xFIP use total BB; wRC+ uses the AL/NL non-pitcher wRC/PA; unbundled seasons warn; every metric carries a `ReferenceStatus` audited in `data/methodology.yaml` and rendered to `docs/METHODOLOGY.md`; golden fixtures from FanGraphs rows; BaseRuns follows Smyth v1/v2; Pythagenpat exponent configurable; ASCII-safe result repr. See `docs/decisions/ADR-0027-published-method-conformance-and-reference-status.md`. |
| **ADR-0028** | **Method Audit of Every Metric and Model, Evidence Tiers, and the Defects It Found** | Accepted | Every metric now reads `matches` or `approximate` with an evidence tier (`golden`/`primary`/`secondary`); 6 open models stay `unverified` with written reasons. Fixes with before/after numbers: Pull/Cent/Oppo% denominator, league-specific K%+/BB%+ for batters and pitchers, Total Average without CS, located-pitch zone rates, bunts excluded from swings, contact quality on balls in play only (Hard-Hit% 39.5 to 33.7), and the default RE24 table replaced by the published FanGraphs matrix. See `docs/decisions/ADR-0028-literature-sweep-and-method-audit.md`. |
| **ADR-0029** | **Park Factor Calculation and a Sourced Park Table** | Accepted | `value.park` computes raw, composite and regressed park factors from the FanGraphs Library method; the bundled table is the 30-team FanGraphs Guts! 2024 snapshot (the old 7-park table differed in several cells); unknown parks warn. See `docs/decisions/ADR-0029-park-factor-calculation.md`. |
| **ADR-0030** | **Game Score, Game Score 2.0 and Off** | Accepted | Adds `game_score` (James), `game_score_v2` (Tango) and `off` (FanGraphs) from formulas read in the literature sweep; Game Score reproduces published games, Game Score 2.0 follows the FanGraphs formula (the article prints no player value). See `docs/decisions/ADR-0030-game-score-and-off.md`. |
| **ADR-0031** | **Base-Advance Average** | Accepted | `add_base_advance_columns` and `base_advance_average` from Hardegree (2005); the paper's sample inning reproduces row by row (14 bases over 57 opportunities). See `docs/decisions/ADR-0031-base-advance-average.md`. |
| **ADR-0032** | **Extended Pythagorean Head-to-Head Probability** | Accepted | `Log5Model.extended_pythagorean_home_win_prob` from Cleary et al. (equations 1.4 and 1.5) with a caller-supplied exponent. See `docs/decisions/ADR-0032-extended-pythagorean.md`. |
| **ADR-0033** | **Bundled League wSB Constant** | Accepted | `lg_wsb` is computed for 1990 to 2025 from league SB, CS and on-base totals and reproduces FanGraphs' published wSB for eight players; `wsb` is now `matches`, `bsr` stays approximate (unsourced wGDP constants). See `docs/decisions/ADR-0033-league-wsb-constant.md`. |
| **ADR-0034** | **Marcel Pitcher Configuration** | Accepted | `MarcelProjector(playing_time_base=...)` makes Tango's pitcher method reachable (weights 3/2/1, innings, 25 or 60 base); hitter playing time reproduces his Beltran example; pitchers relabeled `approximate`. See `docs/decisions/ADR-0034-marcel-pitcher-configuration.md`. |
| **ADR-0035** | **ERA- Follows the FanGraphs Formula** | Accepted | `era_minus` = ERA x (2 - PF/100) / own-league ERA with bundled AL/NL league ERA 1990 to 2025; reproduces the FanGraphs Library table and seven leaderboard pitchers within 0.33 points; FIP- stays approximate. See `docs/decisions/ADR-0035-era-minus-fangraphs-formula.md`. |
| **ADR-0036** | **Shutdown and Meltdown** | Accepted | `shutdown` / `meltdown` per-appearance indicators from the FanGraphs definition (reliever game WPA at or beyond +/-0.06, inclusive); only threshold semantics are testable. See `docs/decisions/ADR-0036-shutdown-meltdown.md`. |
| **ADR-0037** | **Position-Player WAR Components Follow FanGraphs (Opt-In)** | Accepted | New `value/position_war.py`; `WARFramework` uses the FanGraphs replacement formula and innings-based positional proration when given `league_pa` and `defensive_innings`; reproduces 2024 leaderboard components. Defaults unchanged, so the entry stays approximate. See `docs/decisions/ADR-0037-position-player-war-fangraphs-components.md`. |
| **ADR-0038** | **kwERA Uses the FanGraphs Seasonal Constant** | Accepted | `kwera` = C - 12(SO-BB)/TBF with a bundled seasonal C (lgERA + 12(lgSO-lgBB)/lgTBF through 2020; lgERA + 1.887 measured for 2021 to 2025); 13 pitcher seasons match FanGraphs. Replaces the 5.40 default. See `docs/decisions/ADR-0038-kwera-seasonal-constant.md`. |
| **ADR-0039** | **Forecast-Evaluation Utilities** | Accepted | New `sabermetricspy.evaluation`: `mse`, `rmse`, `mae`, `bias`, `brier_score`, `brier_skill_score`, `log_loss`, `calibration_table` (Murphy 1973 decomposition with reported remainder); optional weights; hand-computed tests. See `docs/decisions/ADR-0039-forecast-evaluation.md`. |
